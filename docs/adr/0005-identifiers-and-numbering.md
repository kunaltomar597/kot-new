# ADR-0005: Identifiers and human-facing numbers

Status: Accepted
Date: 2026-09-25
Work package: P0-05
Requirements: ORD-008, ORD-013, BILL-003, TBL-008, INT-005

## Context

Devices create records while offline (waiter drafts, QR orders through the relay) and must never
create duplicates. Humans need short numbers on tickets and invoices.

## Decision

- Every entity id is a UUIDv7 (time-ordered for index locality, safe to generate on any device).
- Idempotency keys are UUIDs generated by the client per submission and stored with the result.
- Human-facing numbers are separate from ids and allocated by the server:
  - order number and KOT number: sequential per business day;
  - takeaway token: sequential per business day;
  - invoice number: gap-free per invoice series per financial year, allocated inside the invoice
    transaction with a row lock (not a PostgreSQL SEQUENCE, which can skip values on rollback),
    formatted by `@rp/domain` `formatInvoiceNumber` (≤ 16 characters).
- External systems' identifiers are stored as `externalId` / `externalRef`, never used as keys.

## Consequences

Invoice allocation serialises invoice creation per series; this is acceptable at the design capacity
(300 orders/hour peak).
