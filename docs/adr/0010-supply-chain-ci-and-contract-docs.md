# ADR-0010: Supply-chain CI baseline and generated contract documents

Status: Accepted
Date: 2026-09-25
Work package: P0-06
Requirements: SEC-013, NFR-M07, INT-002, NFR-M06, UPD-006

## Context

SEC-013 asks for dependency vulnerability scanning, SAST, secret scanning in CI and an SBOM;
NFR-M07 for automated update PRs and a licence check that blocks licences incompatible with
commercial distribution; INT-002 for OpenAPI and AsyncAPI documents generated from the shared Zod
contracts and checked in CI. The P0-06 spec suggests tools "e.g."; this ADR records what was used
and why.

## Decision

- `.github/workflows/security.yml` runs on pull requests, on `main` and weekly (Monday): CodeQL
  (`javascript-typescript`, `security-extended`, no build), `pnpm audit --audit-level high`,
  dependency review on pull requests (fails on high), gitleaks over the full history, the licence
  check, and a CycloneDX 1.7 SBOM from `@cyclonedx/cdxgen` uploaded as an artefact (90 days).
- Third-party actions in `security.yml` are pinned to commit SHAs with the version in a comment;
  Dependabot updates the SHAs. `ci.yml` keeps its major-version tags until Dependabot's first
  grouped Actions PR.
- Secret scanning uses the gitleaks binary through `infra/ci/gitleaks.sh` (pinned version, SHA-256
  verified) instead of `gitleaks-action`, so CI and developers run exactly the same command
  (`pnpm secrets:scan`) and no licence key is needed if the repository moves to an organisation.
- The licence check reads `pnpm licenses list --prod --recursive` and applies
  `infra/ci/license-policy.json`: deny by default, an allow-list of permissive licences, GPL, AGPL
  and SSPL blocked outright (no exception possible), and per-package exceptions with a reason for
  anything else (for example LGPL native binaries). This replaces `license-checker-rseidelsohn`,
  which walks `node_modules` and is unreliable with pnpm's symlinked layout.
- Contract documents are generated by `pnpm contracts:docs` into `docs/api/openapi.json` (OpenAPI
  3.1.1) and `docs/api/asyncapi.yaml` (AsyncAPI 3.1.0). Every exported Zod schema becomes a
  component named after its export; REST paths come from the route registry
  `packages/contracts/src/routes.ts`; channels come from the `DomainEvent` union. A schema whose
  accepted input differs from its parsed output (defaults) gets an extra `<Name>Input` component,
  used for request bodies. `pnpm check` and CI run `pnpm contracts:docs:check`, which fails on
  stale documents.
- Every exported schema has a JSON-schema snapshot (input and output form) in
  `packages/contracts/test/__snapshots__/schemas/<Name>.json`. CI never writes snapshots, so a new or
  changed schema without its committed snapshot fails; the diff shows the contract change in review
  (UPD-006 N-1 discipline).

## Alternatives considered

- `gitleaks-action`: convenient PR comments, but needs a paid licence for organisations and does
  not run locally.
- `license-checker-rseidelsohn`: see above; also an extra dependency for what pnpm already reports.
- A single Vitest snapshot file for all schemas: smaller, but parallel work packages adding schemas
  would conflict on one file; one file per schema merges cleanly.
- Generating OpenAPI with a third-party Zod-to-OpenAPI library: Zod 4's `z.toJSONSchema` with a
  registry already produces 2020-12 schemas with `$ref`s, which OpenAPI 3.1 uses directly.

## Consequences

- A work package that adds or changes a contract must run the contracts tests locally (writes the
  snapshot) and `pnpm contracts:docs`, and commit both; `pnpm check` tells it to.
- A work package that adds an endpoint adds a `ROUTES` entry with its capability and requirement
  IDs; the route's schemas must be exported.
- The auth scheme (P0-09) is not yet in the OpenAPI document; `x-capability` on each operation
  records the enforced permission until then.
- The cdxgen version is pinned in `security.yml` and bumped by hand. Release pipelines (P7) attach
  the SBOM to each release.
- If GitHub's CodeQL "default setup" is switched on for the repository it conflicts with this
  advanced workflow; keep default setup off.
